# M²Shelf 长期决策
## 2026-11-11 局部筛选不触发跨页搜索

集合页的输入框是当前集合筛选器。输入和 Enter 均留在当前集合，保留当前排序、视图与浏览快照；全局搜索由侧栏、窗口菜单或显式命令打开。不能用 Enter 的快捷跳转隐式替换筛选范围。

本次 0.5.17 采用独立末层样式文件修复界面一致性，沿用语义 token 和原页面组件；短窗口的紧凑排版不改变侧栏宽度，海报画框不加 transform。原生窗口栏、阅读器和持久化管线保持既有实现。

## 2026-10-29 显示名称及手动 TMDb 剧集入口

修改显示名称预填当前界面实际标题（含当前语言的提供方标题），已有人工名称仍原样优先。保存后用原生返回的显示名称/人工意图局部更新当前卡片、详情及导航快照，再沿原通道重验；保存期间不重复提交或关闭对话框。名称只属于应用数据库，不修改源目录。

手动TMDb入口支持真人影视及兼容VIDEO的作品和含已索引视频的CONTAINER系列，排除隐藏Root、书籍、动画绑定及多来源虚拟聚合。系列只使用TV身份；普通作品保留原索引自动判断，并可显式选择电影或剧集以纠正模糊命名。打开已有TMDb绑定时选择原提供方及其类型；电影/TV同号结果不得互相标为已绑定。可选mediaType仅属于手动搜索参数；自动匹配仍传空值、遵守原有类型/年份/精确标题/作品边界。绑定、原语言海报、人工封面、取消和过期快照校验保持。增量迁移0036只替换TMDb写入触发器，使有效TV系列能插入、更新和恢复启用；普通作品仍兼容旧Movie载荷，旧绑定、封面及其他数据不重写。备份schema升至36并严格保留32–35旧备份的原触发器校验和恢复升级；应用版本与凭证不变。


## D87 — 进程退出不能抢先丢弃mpv尾部消息，EOF仅核对已提交状态

当前会话取消应立即停止旧写入与通知；子进程退出与管道尾部数据到达是不同条件，不能在读取前仅因进程已退出而结束观察。仍保留原命名管道PID校验、消息/缓冲上限、异步取消、空闲超时及有限重连，不连接用户独立启动的mpv。

只在本文件已确认播放且收到end-file/eof时，发送带原file/owner身份的FINISHED核对事件。不得用进程退出、shutdown、stop、quit、错误或未确认路径推断完成。FINISHED不重复写观看/历史，不撤销手动清空，也不把作品观看/阅读状态自动设置为已完成；前端用原代次和局部更新渠道读取真实已提交结果，避免整页刷新。不同文件/会话及Root边界继续沿用原保护。

## D86 — 删除重复计算，不能把已有就绪数据变成稍后加载

全部资源的目录和穿透两种视图保持同时可用；不得为缩短启动统计而只读取当前投影，再把等待转移到用户切换视图时。启动、导航、状态和图片继续遵守 D80–D85，不加可见刷新、加载页或滚动后补状态。性能结论必须来自实际构建载荷的前后对比，同时检查完整返回数据等价及已有功能。

读取快照内可共享进度来源分组，但必须严格使用原 is_source/group_key 规则，不借用边界不同的写操作成员表，不跨快照复用进度。保持来源排序、分组顺序、有界临时文件投影及真实观看值读取。预取与详情共享已解析的来源计划，不改变操作对象或归属校验。前端可把文字状态订阅下沉，让相同进度确认保留对象引用并省略通知；快照代次、失效标记、重试和真实变更通知不得被绕过。海报 DOM、地址、档位与缓存生命周期不随这项优化改变。

## D85 — 资源库切换复用已验证的集数身份，状态仍随当前快照返回

动画库切换不能重复为全部卡片构造文件详情，尤其系列拥有大量子作品时。普通 Library Browse 在当前 SQLite 读事务中复用 schema25 已为所有 Root 维护的索引 revision，结合数据库身份、Root 当前字段、节点/视频/绑定数量和 TMDb 当前内容构建纯身份缓存入口。数量检查补足旧触发器只递增目标 Root 时的移出边界；TMDb 旧表没有相同触发器，必须读取当前内容。缺少旧 revision 行时回退完整索引流式摘要。命中时直接批量读取当前观看键；未命中、缓存淘汰或相关索引变化仍走原归属和解析算法。两种入口共享既有 4096 项/32 MiB 预算，按实际拥有的内存计量，不能为估算大小再序列化整个系列。不新增持久表或独立进度缓存。观看状态不参与身份摘要，也不保存在此缓存；修改/清空/mpv 的完整事务校验不变。

目录所属 Root 的校验只查询所属 ID，不为校验额外加载父目录活动/绑定/标签。保留隐藏边界、完整 BrowseResult 和异步请求代次；首屏仍含真实进度，不以挂载后补查、旧页面快照直显或提前查询暖机代替。验收必须单独测侧栏 Root 切换，不能用详情打开的速度证明它。

## D84 — 按完整交互就绪验收，合并详情读取并消除强制布局

2026-10-27用户仍能感到点击延迟。标题先出现、观看按钮随后加载不算详情已完成；性能验收需要同时记录内容、封面、可操作观看控件、长任务和实际窗口状态。普通作品、千文件表及数百子作品系列分别测量，不以先调用详情接口暖机的结果冒充首次点击。

原生展示详情可以在同一SQLite快照附加完整观看操作快照，共享归属图和文件投影。D83的有界纯身份缓存按实际来源作品复用；键包含所有身份解析所用的当前索引输入、Root路径/模式、展示模式及外围单文件上下文，排除不影响身份的活动时间与卡片计数。观看状态、修改签名、来源文件名和失效历史必须由当前快照得到，不把过期状态装进身份缓存；原有单事务/过期快照校验保持，须与未缓存算法对照。聚合内联观看身份使用返回详情的真实代表Node，不能用请求中的其他聚合来源ID冒充。

封面使用共享ResizeObserver的实际布局尺寸再选择既有档位；等宽网格在一次提交中只测一个真实封面宽度，以便所有已准备封面在恢复滚动位置前建立正确地址，临时宽度不跨提交保留。不在成百卡片挂载时逐一getBoundingClientRect，也不为无来源占位图测量。离屏内容优化只能保留稳定DOM、图片地址和既有尺寸，不能恢复滚动卸载封面或延后真实进度；不对封面框应用content-visibility，以免妨碍浏览器提前加载图片。新目的地的零位置复位在新DOM插入前处理，非零返回位置在真实目标布局后恢复；不可用延迟复位换取首帧数字。已确认详情在导航请求中保持可见并暂时禁止旧内容操作，取消导航应恢复原内容。重选当前目的地也必须取消更早的在途导航，不能因“当前页相同”直接返回而让旧响应抢走页面。

此迭代保持0.5.15及原schema，不增加数据库迁移、后台进度存储、加载屏、额外原生权限或依赖。回归同时覆盖首帧状态、首次及往返快速滚动、文件行几何/键盘操作、导航竞态、阅读和mpv；区分合成原生验收与私人资源库/干净Windows环境验收。

## D83 — 首帧状态投影不能恢复逐卡片完整详情计算

2026-10-26用户反馈库内文件夹打开变慢。D82的同步首帧要求保留，但集合卡片只需真实计数，不需要完整观看修改签名、失效历史或最近播放文件。展示读取复用同一快照内的来源证据和有界文件解析，批量读取所需观看作用域；修改、清空和mpv继续用完整且已验证的观看快照。不得以另建持久进度表、显示假“未开始”、恢复挂载后补查或牺牲海报稳定性换取速度。

普通视频详情与单Root目录可以只加载所属Root的归属图；同名、绑定、独立作品、忽略边界及拥有视频集合必须与原全库算法一致。跨库聚合详情仍按原全局来源与事务快照处理，不能用单Root优化丢掉其他来源。已看记录只在一次读快照内复用；允许有界进程内复用确定性的纯身份行，但键必须包含完整当前索引输入、展示模式、Root路径及识别模式。缓存不得含已看状态，不得代替文件有效性判断；改名、绑定、文件或归属变化必须换键。性能回归必须覆盖多作品目录、系列子项和单个大作品，并同时检查点击到内容首帧、状态首帧和滚动封面。

## D82 — 观看/阅读摘要必须随集合数据首帧返回

2026-10-26用户再次发现状态延迟。D80的常驻缓存只能解决已查过的值；首次挂载后每16项补查仍会让状态晚于卡片出现。本条替代这种首帧读取方式，不以先显示“未开始”假值、等待滚动或额外加载屏掩盖。

所有会渲染MediaCard的集合、库内目录、收藏、最近、搜索、智能书库及详情子卡片，在原SQLite读快照里投影可选MediaNode.cardProgress。书籍按原详情拥有集批量统计，复用同一个手动/绑定边界CTE；视频共用归属图和原观看身份，只拼装拥有视频，不构造无关资源/子目录/活动数据。不新增schema、进度表、媒体写入或一套观看身份。原生显式card_progress命令仍限制16项，供旧载荷和后台校验使用，不作为正常卡片首帧必经队列。

前端在原生响应交给React之前同步接收摘要，首帧同时有真实状态；请求代次及顺序保护防止旧集合响应或旧校验覆盖新勾选。4096项限制用于跨路由的非活动缓存，已挂载卡片保留其已确认值，不因LRU淘汰变空。导航载荷带前端代次，旧快照保留当前显示并触发重新验证。确认写入和清空仍局部更新；读取错误不能假装没有进度。

此修复不修改D81封面地址/缓存、Windows窗口栏、CSS、版本或数据库结构。验收必须在卡片首次DOM提交时检查状态，不得先等待状态准备完成才开始截图或滚动；还要测真实已看/阅读记录、切页、首屏及封面回归。

## D81 — 稳定原生图片地址与已准备缩略图的直接读取

2026-10-26 用户要求彻底解决 OpenComic 对比中的滚动封面延迟。本条替代 D80、D79及早期封面条目中的前端 Base64/data URL、128 项字节 LRU、离屏释放图片和四路 JS 预解码规则；不改变原 poster_cache 的 key、磁盘格式、四档生成、配额、后台检查点、错误诊断或重试。

封面先完成实际布局测量，再按 CSS 宽度×DPR（上限2）选择现有档位；不先发默认512档再补正确尺寸。每张卡片保留同一个 img 和稳定的 Node/Book 修订地址，使用浏览器原生 lazy 请求调度与同步解码；滚动不移除 src，不做 Canvas、ImageBitmap 或前台重采样。原生 m2poster 只接受索引ID、固定宽度和有界修订参数，不接受文件路径；仅主 WebView 可用，响应限定已校验 JPEG/PNG/WebP。兼容数据URL命令保留供既有显式调用，主展示不再使用。

实测 Windows WebView 不复用自定义协议的 HTTP 缓存，不能只设置 immutable 就宣称问题解决。原生保留32 MiB/4096条编码图片LRU及最多4096个已校验派生文件租约；不缓存第二份解码位图或新增持久封面目录。四个磁盘读取槽复用SQLite连接和已验证缓存作用域；冷请求只查询必要来源，命中租约不再查SQL、打开原书或缩放。每次磁盘命中仍核对缓存根、重解析、规范路径、校验和、签名、尺寸和字节上限。缺失/损坏、旧位置原图、PDF首屏兜底仍回到原管线。

图片版本包含会话、来源、书籍修订、档位及显式封面变更代次。清缓存、换位置和Root变更清除原生状态，旧在途任务不能回填；单项换图或提供方变更只更新相关身份。观看/阅读摘要继续按D80独立常驻，不以图片解码为读取门槛。性能验收必须同时测首屏与首次/往返/切页后的快速滚动，不以人为减慢滚动或提前等全库加载来掩盖延迟。后续代码与交付证据见本地 POSTER_RESOURCE_20261026_REPORT.md。

## D80 — 常驻摘要、SPs文件状态及系列汇总

2026-10-26用户追加：摘要不能依赖滚动才出现，SPs要有勾选及进度，系列要显示观看进度。替代D79及D76中只看可见卡片/系列直属视频的部分规则。摘要以真实身份常驻，4096条小型记录上限、16项批次与单请求保持；后台重新验证保留旧值，已确认的写入结果立即应用。失败与“没有进度”分开，重试有预算，返回页面可以重新尝试。封面URL缓存不随此摘要上限扩大。

SPs只使用独立FILE身份，不伪装普通季集。系列只读取同Root、未忽略的后代，保留其实际所有者和观看键；相同编号在独立作品之间不能互相完成。清空按当前完整快照单事务处理，过期/隐藏/移除来源仍拒绝。详情正文仍按原归属呈现，不为了汇总展开或重分类子作品。

来源标题保护由分页与观看共用；显式季集的快速投影提取既有parser语法，不另写一套识别规则。直属/分碟文件只在既有语法已经排除季集标记后省略完整语义解析，不能跳过季0或补充内容判定。普通系列的单集写入限制在原观看scope内；跨版本传播仍仅限经过验证的聚合作品。

图像预解码只缓存尺寸元数据，最多128条；不增加图片副本缓存、重采样或持久封面管线。相同源图保持同一显示元素，来源改变仍经过原错误和修订边界。请求订阅释放与已显示图像释放分开：屏外精确URL真正离开有界LRU时才释放其最后引用，不能单靠滚动退出清空。可见、预热、保护观察状态取并集；保留四路读取和原缓存容量。

## D79 — 视频分页与卡片进度是索引上的有界展示

2026-10-26：正片/SPs/其他视频只投影既有详情拥有的文件，不新建来源、不扫描磁盘、不改变独立作品边界。后端统一复用现有补充目录、结构化季集及分碟证据，并返回逐文件分页；前端只切换本地活动分页，保持原ID、播放及观看回调。无续播记录时首播优先正片，不能因字母排序先播放NCOP等补充文件。

海报进度使用现有逐集/阅读身份，不把历史时间或播放次数解释为完成。原生只读批量接口每批最多16项，视频共用一次轻量归属图；WebView只有一个进度请求在途、256项内存上限、可见卡片订阅及过期代次保护。它不是新的持久进度缓存或封面加载门槛；容量淘汰不能导致活跃卡片无限重查。未识别的视频不虚构季集总数。

集合页标签/状态折叠与搜索页五个显式条件是不同页面的已确认需求，不能相互覆盖。卡片名称和副信息收紧，但原海报帧、稳定本地缩略图管线及Windows窗口栏不变。路径编辑属于同一次建库草稿，编辑对话框暂挂原向导而不销毁草稿，原生验证及创建行为保持。

## D78 — 资源库在全部资源中的可见性是独立展示偏好

## D39：别称补全静默且可续跑，搜索复用集合顶栏

不提供用户手动同步入口。自动匹配在原有详情预算内补全高置信胜出项，并在详情参与最终冲突检查之后绑定；详情成功与别称完成记录一并保存。已有绑定在首次启动读取唯一 Subject 快照并逐条补全，有界请求和单工作线程保护，空结果也完成；失败部分后续启动续跑，已完成部分不重复访问。后台补全只在别称内容变化时刷新当前索引显示，导航期间不恢复旧详情。搜索页视觉排版现依 D47，查询和历史恢复不变。

## D37：排序字段与方向分离，观看时间来自本地播放记录

保留已有 per-scope 的 field-direction 持久化值，增加 watched-asc/desc；UI 显示四种字段与单独方向按钮。观看时间使用应用成功启动播放器后保存的 watch_history，按可见子树和作品来源聚合，未知值双向置后。更新时间正文使用相对时间，完整时间保留在悬停提示，共享单一计时器避免每张卡片创建一个 interval。

## D38：侧栏搜索默认全库，官方别称属于绑定元数据

侧栏进入和重入搜索保留关键词但重置为全库，明确替代沿用 selectedRootId 的旧行为；目录内搜索与历史返回仍支持限定范围，搜索页始终显示可切换范围。官方别称与用于自动匹配的 confirmed_title_aliases 区分，新增 JSON 列随绑定保存并在本地查询。按用户修订，移除手动同步入口。识别时自动补全，首次启动为已有绑定静默补全；migration 0013 保存按 Subject ID/type 去重的完成状态和别称缓存。成功空结果也标记完成，后续新绑定复用缓存，网络失败保留进度、之后续跑；只修改仍指向同一 Subject 的绑定。

## D33：作品聚合是索引上的只读展示

全部资源默认保留原目录卡片；设置中的“全部资源穿透显示”开启时才使用作品平铺与来源聚合。此要求明确替代 PR 原先默认按作品展示的选择，新旧数据库未保存值均为 false。选择保存在 SQLite settings，立即生效并跨重启恢复，不由导航快照或另一个页面下拉框覆盖。开关只控制全部资源的展示，不回退 PR 的分类、扫描、Root 识别模式或详情规则。优先使用 Bangumi Subject 类型与 ID 归并来源；未绑定的文件作品只在同一物理目录内使用带季度、年份与版本的保守标题键归并。文件夹来源需要共同绑定才跨目录归并，避免把重名、续作和不同版本强行混合。聚合不改变 Node 路径身份或用户元数据，视频播放仍使用原始 MediaFile ID。编辑模式与来源列表始终提供原始 Node 操作入口。

## D34：启动静默增量更新复用扫描生命周期

启用设置后，每次前端启动在初始化成功与监听就绪后自动检查一次。新建数据库默认启用；旧库缺少已保存设置时默认关闭，已有 true/false 保留；已有扫描或更新恢复流程期间不重复启动。启动检查静默运行，不显示进度条或完成/失败 toast；没有源目录差异时不重载页面数据。有变化时沿用当前导航状态重载索引。手动扫描仍显示进度、取消和结果反馈。

增量检查比较应用 SQLite 中保存的目录项快照（名称、类型、文件大小、修改时间），只读枚举目录，不读取媒体内容。不依赖根目录修改时间推断深层变化，以兼容关机期间变更、移动硬盘及 NAS。文件夹识别模式只索引变化目录并复用未变化子树，局部更新继续刷新祖先计数；文件识别模式也跳过未变化的物理子目录，并保留对应扁平 Node、附件与 BDMV 的清理标记和计数。未变化子树不进入自动匹配。

首次检查、扩展名/识别方式/隐藏状态变化或手动扫描后重新建立基线。读取失败或取消不推进快照，不可访问 Root 保留旧索引。扫描互斥、源只读和应用元数据保留规则不变；快照以 additive migration 0011 加入，不重建旧数据库。本功能不下载媒体或自动安装软件更新。

## D35：隐藏条目可从索引恢复

设置页“已隐藏条目”从 SQLite 列出所有层级的 `IGNORED` Node，包含无视频的资源目录和独立隐藏的子节点，源盘离线也可读取。恢复复用 `reset_node_type`，按现有自动分类规则重新识别，不声称恢复隐藏前的人工类型；保留名称、绑定、封面、标签和收藏。恢复父目录不会取消子节点独立设置的忽略标记，恢复子节点也不会擅自取消祖先隐藏。界面明确提示分别恢复。无需新增数据库结构。

## D36：最后更新时间来自源文件索引

`modified-desc` / `modified-asc` 使用已有 settings 排序偏好，无需迁移。`MediaNode.latest_file_modified_at` 在 Rust 中按需批量从媒体和附件的 `modified_at` 聚合，并统一为 UTC；目录包括可见后代，聚合作品取所有来源的最大值。不得使用会被扫描、改名或绑定更新的 Node `updated_at` 代替。时间未知始终置后，启用时间排序才显示时间。隐藏条目入口置于设置的资源库管理区域。

## D01：媒体源永远只读

Library Root 是用户资产。扫描、重命名显示名、分类、绑定、标签、收藏夹和观看记录只修改应用数据库或缓存，绝不修改真实媒体目录。

## D02：SQLite 是应用元数据的权威来源

所有数据库访问保留在 Rust。WebView 只通过类型化 Tauri 命令读取和修改数据。Schema 演进使用向前兼容的增量 migration，不重建或清空旧数据库。

## D03：路径是当前索引身份

Root、Node 和文件以规范化绝对路径识别。外部移动或改名通过重新扫描反映；应用不为保留身份而移动源文件。父 Node 必须与子 Node 属于同一 Root。Library Root 之间不得相等或互为祖先/子孙；添加时以 Windows 路径组件和大小写语义在事务内拒绝，扫描时再次防御旧数据库中的重叠项，避免全局路径身份把 Node 改挂到另一 Root 并在删除时级联清除元数据。

## D04：分类以视频分布为基础

Work / Container / Mixed 使用直接视频、子媒体分支和总视频数判断；UI 分别表达为作品、系列和其他资源。人工覆盖在重扫后保留。非视频附件不单独成为作品。

## D05：Bangumi 是可纠正的展示元数据

Bangumi 绑定、标题和封面不能重命名源目录。普通自动流程只为未绑定且合格的 Node 搜索并写入元数据，不覆盖已有绑定或手工封面；已有绑定缺失自动封面时只允许按原 Subject 恢复封面，不重新搜索或改绑。人工搜索始终作为纠错入口。

## D06：最高合格候选直接绑定，硬冲突仍阻断

主关键词的 Bangumi 第一项在本地证据足够具体时可以提升到直接门槛，但仍须接受季、强年份、版本和类型保护。普通自动范围依 D41 仅限逻辑作品，系列保留手动绑定。人工确认别名按证据优先级选择首个有历史记录的别名；该别名自身的所有观察必须一致，否则回退普通官方搜索，不因更弱别名猜测。别名入库保留有效季数与年份，只提供标题精确信号而不能伪造官方结构证据；唯一映射获得官方详情优先级，普通的最多三次官方搜索仍作为别名过期、详情失败或硬冲突时的候选回退。

最多三个官方查询，从当前 Node 的显示名、真实目录或文件名、视频和有用父目录得到结构化证据，多语言评分并检查季度、强年份、版本和类型冲突。候选池按提供方排名公平合并；高置信结果只补胜出项详情以自动保存官方别称，其余结果最多补全初步评分最高的五个候选并使用两路小批并发。单次匹配运行的新详情请求总数限制为 256，并复用本轮相同 Subject 的结果；在剩余预算允许时为每个后续 Node 预留至少一次未缓存详情机会，详情提供方级故障触发整轮熔断，预算耗尽或熔断后继续以有界搜索元数据评分。

自动匹配不再设置领先分差或用户可见的“待确认”档位：排序后的最高候选达到配置的直接门槛、没有上述硬冲突时即可写入。分数相同时以提供方排名稳定决胜。保留更高的自动阈值只用于详情补全快路径，不作为唯一写入门槛。此前的待确认结果没有持久队列或用户操作入口，却会阻止人工搜索首项已经明确的作品自动绑定，因此本决策明确替代旧的“只有高置信且领先足够才写入”规则。动画 type 2 与真人影视 type 6 适用相同规则，其他 Subject 类型仍为强冲突；明确批量重匹配也使用相同门槛。Subject 类型随绑定持久化，旧绑定通过增量 migration 默认 type 2。

用户明确选择 Bangumi Subject 时，可以把该 Node 自身的有界清洗标题作为应用本地确认别名写入 SQLite；父目录上下文、媒体路径和自动匹配不得被学习为别名。复用时必须由同一规范化别名的所有观察一致指向一个受支持 Subject，出现歧义就回退普通官方搜索，并继续执行当前 Node 的全部硬冲突保护。清除或替换来源绑定以及删除来源 Node 时删除对应观察。该机制用于补足 Bangumi 未收录的明确译名，不增加第三方标题服务，也不把本地标题发送给新的服务。

## D07：补充目录默认不参与自动匹配

无独立人工分类或绑定的 SP、OVA、Extras 等补充目录不生成独立作品候选；所属视频由父逻辑作品展示和匹配。用户可明确分类或单独绑定，形成独立边界。此范围依 D41 替代仅检查父直属视频的旧规则。

## D08：绑定与封面状态分离

封面下载失败不删除有效绑定。失败原因可见且可重试；清缓存或缓存文件丢失后，普通扫描/匹配可从保留的绑定 URL 只恢复自动封面。Bangumi 和手工封面均写入应用缓存，不写入媒体目录。

## D09：自定义缓存必须可证明安全

活动缓存不能位于任何 Library Root 内。切换目录不自动迁移或删除旧缓存，旧路径仍可读取。清理只触及应用确认拥有的活动缓存文件，绝不把用户选择目录整体当作可删除区域。

手工封面复制、Bangumi 下载提交和旧缓存读取都校验大小、真实格式与像素尺寸；Bangumi 下载与手工封面都经目标目录内的唯一临时文件原子替换，任何验证或提交失败都不得先删除已有封面。封面 CDN 的提供方级错误在单次匹配运行内熔断，条目级 404、无图或坏内容不误触发整轮熔断。普通缓存读写共享进程内操作屏障，清理独占屏障并拒绝与后台扫描/自动匹配并行，以保证缓存文件和 SQLite 路径状态一致。

## D10：本地化只影响展示

界面支持 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`。绑定标题按当前语言、中文、Bangumi 主标题、数据库显示名、真实目录名回退。语言切换不改变源名称或路径，系列后缀也是展示层文本。

## D11：用户文案集中管理

所有用户可见文本、ARIA、菜单和错误摘要进入类型化 i18n。Rust 内部诊断不直接作为最终界面文案；前端按错误类别显示可本地化摘要。

## D12：主题使用语义变量

支持 system、light、dark。组件使用共享的背景、表面、文字、边框、强调和状态变量；暗色模式不是颜色反转。应用运行时响应系统主题变化。

## D13：字体来自系统

界面使用 Windows/system UI 字体栈，不捆绑或分发 `.ttf`、`.otf`、`.ttc`。

## D14：Logo 母版不可再加工

`src-tauri/icons/icon-source.png` 是当前唯一权威母版。所有 PNG 和 ICO 只按完整画布等比缩放生成，不裁切、描摹、锐化、重排、重着色或修改字形。Windows ICO 保留 256、128、64、48、32、24、16 像素帧，256 帧置首。

## D15：标签是应用本地多对多元数据

标签按规范化名称唯一，可跨 Root 和批量管理。系统分类标签与用户标签在视觉上区分。批量写入先验证完整 Node 集，再以事务提交。

## D16：收藏夹是一层命名集合

一个 Node 可属于多个收藏夹，收藏夹不嵌套。删除集合不删除 Node、绑定或媒体；扫描保留成员关系，Node 删除时由外键清理。批量成员修改使用事务。

## D17：最近观看只记录成功启动

只有播放器进程成功 spawn 后才更新 Node 的最近观看。每个 Node 保留最新时间和计数；不读取播放器历史，不推断进度，不写入媒体文件。

## D18：播放器保持外部和通用

产品不内置播放器，UI 统一使用“播放器”。兼容键 `mpv_path` 保留，mpv 是示例。程序和媒体路径作为独立字面参数传给原生进程，不拼接 shell。

播放器测试必须有短超时；异常程序不得长期占用应用线程。

## D19：Windows 文件定位使用原生契约

定位文件必须在 Explorer 中选中准确目标，并保持 Unicode、空格和特殊字符为字面路径。普通附件交给 Windows 默认关联程序打开。

## D20：导航历史与目的地快照分工

打开新详情从顶部开始；返回、`Alt+Left` 和 WebView 历史在有快照时恢复原视图。全部资源、搜索、最近观看、收藏夹和各 Root 分别保留会话内快照。Root 与收藏夹恢复时重新查询当前业务行，避免快照覆盖新扫描或新元数据。集合加载和当前视图刷新使用独立请求代次，只有最新请求可以提交状态或结束 loading，防止旧响应覆盖刚完成的绑定、改名、扫描或导航结果。

## D21：集合排序按作用域持久化

全部资源、资源库浏览和收藏夹分别在 SQLite `settings` 保存排序。排序键独立于设置页的完整 `AppSettings`，设置自动保存不得覆盖它们。

## D22：窗口尺寸由原生生命周期保存

主窗口隐藏创建，在首次显示前恢复通过校验的尺寸，并等待前端应用持久化主题、提交首屏后再显示；关闭时只保存一次最终有效值。异常或超出显示器范围的数据回退到安全默认值，不能为了恢复尺寸先显示默认窗口再调整。

## D23：直接显示持久缩略图，海报不再二次重绘

2026-10-08 用户明确要求参照 OpenComic，使用扫描匹配后准备好的本地封面稳定显示，替代此前预览图/渐进 ImageBitmap/Canvas 的双渲染路径。核对上游 `ollm/OpenComic` 提交 `3e366371cc5df2625c319d50222b4c8d8c54f25b`：`scripts/cache.js` 按 DPR/尺寸准备并复用质量 95 的 JPEG，`templates/index.content.right.module.item.html` 用图片元素显示缓存路径。这里只采用缓存及直接显示的方式，保留 M²Shelf 的 Rust IPC 和源只读边界，不引入 Electron、Sharp 或上游代码依赖。

M²Shelf 原有 Rust 四档 Lanczos/方向/ICC/透明度、原子校验写入、检查点、失败重试及容量限制保持；有效 v2 派生文件无需清理或重建。`PosterImage` 统一为一个异步解码图片，首次显示前确定 cover/contain，不监听滚动、不做 ResizeObserver 重采样、不切换 Canvas 或使用位图 LRU。父级实际滚动根的预热、四路 IPC、128 项/32 MiB 精确 data URL LRU 和修订保护保留；64 项目标只控制请求保留，不释放已显示图片。无 transform 动画。滚动条槽及图片框尺寸稳定，类型角标在左上角；2026-10-09 按后续定向要求，标题下数量与用户标签摘要共用固定高度元信息行，不再预留独立标签空行。此决定替代旧 Canvas/预览保留要求，防止以后再次引入可见的二次切换。

## D24：网络与桌面权限保持最小

Bangumi 网络访问限于批准的官方主机，使用 TLS、连接/总超时、搜索/详情响应体上限和有界结果。瞬时网络错误、HTTP 429 与服务器错误最多重试一次，数字 `Retry-After` 截断到两秒；一次提供方级搜索失败停止该匹配运行的剩余在线阶段，避免按 Node 放大故障等待。Tauri capability、CSP、asset scope、文件对话框与进程能力只开放当前功能需要的范围。

## D25：公开仓库与发布不携带私密上下文

不得提交访问令牌、密钥、凭据 URL、个人文件路径、真实媒体索引、私密截图、聊天记录或一次性需求全文。公开 Windows 构建通过正式脚本生成，并扫描可执行文件和 Portable 内容中的构建者路径。

## D26：发布产物必须可验证

正式 Windows 发布使用 `scripts/build_windows_release.ps1`，验证版本、x64 架构、多帧图标、校验和、隐私和启动。Portable 表示应用本体免安装，不表示不使用 Windows 应用数据目录。

## D27：稳定更新使用固定且有签名的 Release 契约

客户端只从固定的 M²Shelf GitHub Release `latest.json` 检查更新，并只接受严格大于当前版本的规范 `major.minor.patch` SemVer。预发布、build metadata、相同版本和降级被拒绝。清单严格包含四语言说明，以及固定版本化的 `windows-x64-portable` 和 `windows-x64-nsis` 资产；URL、文件名、长度、SHA-256 或 schema 不符即失败。

引导版本可能暂时高于尚未携带清单的最新公开 Release。仅当固定地址返回 404 且 GitHub 最终地址严格等于本仓库的 `v{canonical-version}/latest.json` 时，客户端可读取该 tag，并只在 tag 不高于当前版本时返回“无更新”。更高 tag 缺少清单继续失败；该兼容分支不产生候选资产，也不能绕过清单、SHA-256 或 Ed25519。

Ed25519 签名绑定协议域、应用 ID、版本、平台、长度和 SHA-256，客户端在下载结束和执行前都验证。仅有清单自带 SHA-256 不构成信任。启动自动检查只提示，不自动下载或安装；后两步必须是用户明确操作。设置页将自动检查开关与手动检查按钮保持为同层级操作；手动检查无更新或失败仅给出短提示，只有有效新版本才打开更新详情。

## D28：更新信任根长期不变，生产 seed 由加密 USB 携带

生产 Ed25519 私钥绝不进入仓库、GitHub Secrets、Actions、Release、命令行、环境变量、日志、临时文件或项目文档。自 `v0.5.11` 起，现有 production seed 与 `src-tauri/update-public-key.txt` 是长期更新信任根；普通发版不得重新生成 seed 或替换公钥。任何真实 production key/seed 的生成、迁移、替换或轮换都必须停止发布并先取得项目所有者的明确确认。随软件分发的 `M2ShelfUpdater.exe` 仍不提供密钥生成能力，客户端 updater、Ed25519 消息格式和 Release schema 均不因密钥存储方式改变。

现有 CurrentUser-DPAPI 文件仅作为一次性迁移源和保留的恢复副本，不再进入日常签名。独立、非分发的 `tools/portable-key-tool migrate-dpapi` 在原 DPAPI 所属 Windows 用户中解出同一个 32 字节 seed，先核对当前公钥，再用 Argon2id 和 XChaCha20-Poly1305 写入 USB 固定目录的 `encrypted-private-key.m2key`；迁移后重新解密、核对公钥和确定性签名，且绝不删除或覆盖旧 DPAPI 文件。Agent 只允许用合成测试 seed 编译和验证流程，不得寻找、读取或迁移真实生产文件。

日常发版只使用 `scripts/sign_update_from_usb.ps1` 和 `tools/portable-key-tool sign-release`：插入密钥盘、交互输入密码、在 Rust 进程内解密并调用与客户端共享的签名函数、立即用当前公钥验签、输出既有八项正式文件和 `SIGNED-RETURN`，随后拔出 USB。密码与明文 seed 不离开该进程，不传给 PowerShell 或子进程，也不产生长期缓存。`verify-key` 只验证 USB 密钥是否仍对应当前公钥，不产生签名。该可移动加密容器不绑定 Windows 用户或单台电脑；密钥盘丢失但没有密码时不能直接签名。

`scripts/publish_signed_release.ps1` 是正式发布入口。CI provenance 只是核对元数据，生产签名还必须依赖受信 Artifact Attestation 或隔离环境独立构建得到的候选摘要。发布脚本在修改 GitHub 前 fail-closed 验证干净工作树、不可变 tag/commit、全部本地哈希/签名/清单，并通过独立指纹固定且身份匹配的 helper 对两个资产执行真实 Ed25519 公钥验签；上传到草稿后强制远端名称、大小和 SHA-256 digest 完全匹配再公开。已发布 Release 不修改或替换。

## D29：Portable 更新是可回滚事务

Portable 更新只在带合法 marker 且不与任何 Library Root 重叠的安装目录运行。主程序使用随当前安装分发的可信 `M2ShelfUpdater.exe`，先取得 SQLite 单写入屏障、建立一致快照和受路径约束的事务，并将屏障保留到旧进程退出。helper 必须全程持有独立 Windows 命名更新互斥锁，在旧程序仍存活时锁定、复验并密封 ZIP，完成所有可预检步骤后原子写入 helper-ready；主程序仅在收到匹配版本回执后退出。普通启动必须等待 helper 锁；只有新版子进程携带的规范事务 ID 能认证精确活动事务、当前可执行文件、目标版本和 `Launched` 阶段时才可绕过等待。应用同时保持普通 Windows 单实例。

D54 之前的 helper 只接受固定五文件（当前本地扩展为精确八文件，见 D54）、扁平、无链接、无路径穿越且有界的 Portable ZIP，在同卷暂存与备份目录中操作，并最后替换 `M2Shelf.exe`。更新缓存根、版本目录、事务根和事务目录都必须是解析后仍属于应用目录且不与 Library Root 重叠的普通非重解析目录；启动恢复与清理在枚举前重复校验，只删除严格识别的更新器文件，不能穿过链接递归清理。新版本必须写入精确版本健康回执并继续存活完整三秒。helper 随后先原子记录保留事务材料的终态 `Completed`，清理成功后才清除保留标记；启动恢复续作中断的 `Completed` 清理，而不把成功事务误判为恢复故障。失败时先有界确认新进程终止，再逆序回滚文件；SQLite 快照以长度、SHA-256 和 `quick_check` 复验，当前 WAL/SHM 必须完整预检后隔离，主库使用保留失败版本备份的原子替换。无法确认终止、验证快照或安全恢复时不得覆盖实时数据库，应标记 `RECOVERY_REQUIRED` 并保留材料。异常终止留下的严格可识别非终态事务同样转为 `RECOVERY_REQUIRED`，不执行缺少可靠日志的猜测式自动回滚。两类恢复提示使用四语言持久对话框，只有用户明确确认后才删除磁盘通知。任何更新临时文件、备份和回执都不能进入媒体源。

## D30：Windows 更新只支持 NSIS 与 Portable 稳定通道

更新清单只提供 NSIS 安装器和 Portable ZIP，不提供 MSI、测试版通道、静默安装或自动降级，避免同一客户端存在含义不同的安装路径。`v0.5.8` 仅作为 CI 失败的不可变历史 tag 保留，`v0.5.9` 仅作为最终修复前创建且未公开的不可变历史 tag 保留，`v0.5.10` 仅作为最终匹配修复和生产密钥轮换前创建的不可变未发布 tag 保留；三者都没有 Release、资产或 `latest.json`，不能移动、复用或授权更新。`0.5.11` 被指定为首个包含更新客户端与 Portable helper 的新信任根引导版本，必须在受信 attestation、隔离签名和正式发布完成后才能称为公开版本；`0.5.7` 及更早用户和任何旧公钥测试包用户必须手动安装 `0.5.11` 一次，此事实不得被后续文案或发布流程隐藏。

## D31：后台扫描生命周期必须串行

扫描、匹配现有资源、清缓存、删除 Library Root 和进入更新替换在 Rust 后端共享生命周期门禁。活跃状态覆盖后台 worker 的完整寿命，而不只覆盖可见进度；终态事件之后仍在收尾的 worker 会阻止第二次启动。手动 Bangumi 弹窗的异步预填、搜索和绑定结果同时绑定请求代次与 Node ID，过期结果只能被丢弃。

## D32：资源库识别方式在创建时固定

添加 Library Root 时必须选择 `FOLDER` 或 `VIDEO_FILE`，并把选择保存在 `library_roots`。旧 Root 通过增量 migration 默认 `FOLDER`，其目录树与分类逻辑不变。`VIDEO_FILE` 递归读取但把每个普通视频按真实文件路径创建为隐藏 Root 的直接 Work，使全部资源、搜索、详情、标签、收藏、最近观看和 Bangumi 绑定复用同一 Node 契约；BDMV 仍是一套结构一个 Work。模式不在原地切换，避免改变 Node 路径身份并级联丢失绑定等应用元数据。

文件 Node 不是目录，因此其重扫请求由后端升级为整 Root 扫描。只有无读取错误的完整文件模式扫描才清理未见旧 Node，媒体源始终只读。

## D70：收藏状态与最近活动使用真实的类型身份

## D71：收藏恢复只在没有旧连接的重启阶段替换

备份必须通过 SQLite 一致性快照、schema/完整性/外键和逐项摘要校验；非敏感设置白名单并清理空闲页，不能导出 Credential Manager 或私人令牌。用户确认后只写入应用自有的暂存/事务标记，恢复启动子进程须先等待旧进程退出，再遵循普通单实例锁；该等待参数不提供任何锁绕过权限。下一次启动在建立原数据库连接之前原子替换。Committing 中断恢复到已验证快照，终态清理可重入；手工原件使用新代次位置，不覆盖旧原件。离线媒体路径保留原索引，当前本机凭证保留。此事务只处理收藏数据库和手工封面，不替换程序，不复用生产更新签名流程。

## D72：续卷与观看状态沿用真实身份，页面预览不属于封面缓存

续卷读取现有索引与系列关系，拒绝仅凭作者目录或相似前缀关联；源盘可读性由已有安全打开入口验证。切卷必须等待当前进度保存成功并再次验证归属快照，不能把旧册位置带给新册，也不能自动修改收藏完成状态。文字末尾须依据实际排版尾部；没有可靠结束证据时继续本册。阅读会话容器跨册保持全屏，原浏览返回层级不增加。

逐集已看属于应用数据库的独立记录。2026-10-25按用户要求，文件行双击且播放器成功启动后自动设置已看；单击播放按钮不改变它，启动失败也不改变。保留手动勾选和撤销。唯一季集和文件回退均须通过现有作品归属验证；不同剪辑、季集或提供方边界不能串状态。保留无法安全映射的旧记录而不猜测迁移。schema34备份包含该记录及其来源修订，32/33旧备份先独立验证再升级。

漫画/图片/PDF在末页继续翻阅时按用户打开的可见书籍列表前进；这个明确列表顺序不属于“推断系列”，因此不使用卷号连续性门槛。只传递有界索引身份，打开仍经过原生Root/修订/文件安全边界，保存失败或目标变化不能切书；不跳过或强制提升附件身份，不在末页刚出现时抢走页面。文字书和缺少列表上下文时仍用D72的保守规则。
