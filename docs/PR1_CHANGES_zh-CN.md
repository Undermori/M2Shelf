# PR #1 相比首次提交的修改说明

对比基准是 PR 首次提交 `73c51ca`。本次保留真实目录、Node 与文件 ID，作品继续从本地索引派生；全部变化都不整理或改写媒体文件。

| 功能 | 首次 PR 的问题或限制 | 本次修改后的行为 |
|---|---|---|
| 作品识别 | 直属有视频的其他资源也可能进入作品库 | 分类、所属内容、作品库及普通自动匹配共用逻辑作品集合；仅收集有所属视频的 WORK/AUTO_WORK |
| 多碟目录 | CD1/CD2 等容易分别成为作品 | 根据完整编号目录名、父标题及无冲突结构保守归属；不同季度、标题、绑定和人工独立分类保留边界 |
| 子目录视频 | 特典等内容需要点进目录 | 在“作品中的其他资源”默认递归平铺，显示相对目录和来源，使用原始文件 ID 播放与定位 |
| 聚合编辑 | 看似修改作品，实际上可能只修改代表来源 | Bangumi 绑定、改绑、清除和封面按整组执行；其他编辑先选择具体来源 |
| 并发与事务 | 网络期间状态改变，以及提交后采集快照，可能造成范围不一致 | 完整来源校验、单事务绑定、事务内封面快照、过期写入拒绝；封面失败保留有效绑定 |
| 大组与快照 | 普通批量上限可能拒绝千来源作品；无关状态可能打断操作 | 作品组独立验证，成员关系一次计算复用；播放、标签不使绑定失效，归属与独立边界变化会失效 |
| 封面恢复 | 损坏文件仍存在时可能无法重试 | 有界缓存校验，加上明确的前端解码失败来源；只修复需要的自动封面，保护手工封面 |
| 历史别称 | 一次运行可能连续补全大量 Subject | Rust 维护每次运行 32 个不同 Subject 预算，失败占预算，游标轮换、空结果完成、故障熔断 |
| 启动扫描 | 旧库可能在升级后突然全盘扫描，失败又缺少提示 | 旧库无设置默认关闭，新库默认开启，已有选择保留；首次开启实际更新后再保存基线 |
| 扫描失败 | 用户难以知道后台更新失败 | 每库持久健康记录、设置中查看和重试、侧栏提示；失败库保留未读索引及旧基线，成功库独立结算 |
| 一致性 | 分类和祖先刷新可能部分提交，详情可能混合不同状态 | 单条分类事务化；普通/聚合详情、目录浏览和作品列表共用 SQLite 读取快照；隐藏或移除的旧详情拒绝读取并返回资源库 |
| 原生操作 | Shell 精确选择需要正确的 COM 初始化 | 补齐线程 COM 生命周期保护；特殊字符文件路径使用字面参数播放和准确定位 |
| 署名与入口 | 原作者署名已有，当前贡献者未显示 | “设置 → 关于”保留森下Undermori及现有链接，增加“功能改进与维护：Juvenile_A”；构建日期准确显示 |
| 文档与工程 | 缺少 PR Checks，部分文案和迁移摘要过时 | 增加独立 Windows PR 质量 workflow；同步四语言 README、隐藏恢复入口、产品文档和易读运行机制说明 |
| 开发预览 | 打包时 Vite 监听临时 EXE，可能因 Windows 文件锁退出 | 开发热更新排除 Portable、测试及工具产物目录，继续监听前端源码 |

本地 PR 构建保留 0.5.11，不改变已发布版本资产或更新公钥。系列继续承担真实目录组织，作品库负责跨目录平铺及来源聚合；解除绑定后允许依据剩余本地证据重新分组。
