# M²Shelf 产品规格

## 0.5.13 当前功能范围

当前版本整合下方已实现的资源库、智能书籍组织、内置阅读、海报缓存与 TMDb 电影匹配；各次 0.5.12 RC 的“未发布”标注属于历史记录。下载只展示安装包、Portable 压缩包及自动更新必需的 latest.json，Portable 内部运行文件不精简。当前用户说明以四语言 README 为入口，发布状态以 GitHub Release 为准。

## 2026-10-10 电影名称与既有海报修复（当前）

真人电影解析支持复合音轨、语言标记、BD/HD1080P、流媒体来源、Extended Cut、未知压制组、双语和嵌套广播片名。先分离片名与可靠发布年，再查询；保留 1917、2046、Blade Runner 2049 等标题数字。官方别名需有界详情核验，仍要求同年、允许类型、精确片名/官方别名和唯一候选，不按首条或模糊近似强行绑定。

新自动及手动选择 TMDb 电影均使用原始语言海报；匹配当前资源时可升级既有 TMDb 的旧提供方封面，无需删除资源库或解除绑定。升级后本地复用，失败保留旧图和绑定；用户手工选图、原有 Bangumi 绑定及停用的 TMDb 记录保持。界面语言不决定海报语言，原始中文电影仍可使用中文海报。详见 D62 与 `MOVIE_MATCHING_20261010.md`。

## 2026-10-10 v5：真人电影直接 TMDb 与统一绑定栏

此节替代下方 v4/D59/D60 中真人电影先 Bangumi 后 TMDb 的历史策略，其余行为保持。LIVE_ACTION 独立单视频电影，两识别模式的首次扫描、重扫和未绑定重新匹配直接使用 TMDb movie；自动过程不搜索、选择或绑定 Bangumi。季集/非电影继续原策略。复用已清洗片名、年份及自身别名；查询可缺年，自动绑定必须具有可靠年份、精确标题、唯一候选、类型与官方详情复核。无凭证/冲突/失败保持未匹配，设置保留可追踪诊断。库/全局自动开关、已有任一提供方绑定、人工选择和封面优先级保持。

新自动电影封面按官方原始语言和海报语言证据选择，优先原始语言、其次无语言或其他可用官方海报，不依界面语言强选地区版，不虚构国家归属。封面失败保留绑定及重试；人工封面不变。Bangumi/TMDb 详情绑定栏共用布局、焦点和动作层级，长标题在小窗口换行，动作不挤压文字；TMDb 来源链接打开当前绑定电影的官方页面。v5 不改变 Debug、F5、书籍、扫描结构或数据库 schema。

## 2026-10-10 追加：电影自动查询与可执行调试操作

LIVE_ACTION 的未绑定独立单视频电影，首次扫描、重扫及显式重新匹配都可在 Bangumi 未可靠绑定后尝试 TMDb，仍遵守全局/库自动策略。搜索接受无年份，绑定仍要求可靠年份、精确自身标题/可信别名、唯一电影候选与详情复核。清洗/来源优先级由 Bangumi 与 TMDb 共用；仅首次无结果时有界尝试别名，不绕过候选歧义。设置 TMDb 区域提供按需展开的最近自动查询记录与刷新，失败原因和未查询分别呈现。此项替代 D59/下方历史描述中“强年份是查询前提”及“仅尝试一次”的限制。

调试菜单除重新加载 F5 外提供返回、上一页、下一页、全屏、添加/移除书签。复用现有业务回调，按当前阅读器和边界禁用，动作与键位左右对齐；替代原静态快捷键说明。原生 F5 不拦截、Ctrl+R 与菜单保存/禁用保护维持现状；这两条路径的保护范围不得混称。详见 D60 和 `MOVIE_DEBUG_V4_20261010.md`。

## 2026-10-10 追加：匹配结果精修与真人电影自动备用来源

仅 LIVE_ACTION 的未绑定单视频 Work/AUTO_WORK，在全局与资源库自动关联均开启、已有有效 TMDb 配置时，Bangumi 未匹配或请求失败后可自动尝试一次 TMDb movie 查询。FOLDER 和 VIDEO_FILE 都适用。必须具备强年份、自己的精确标题、唯一候选和官方详情复核；拒绝电视剧、动画、纪录片、含季集证据或证据不足的来源。已有任一提供方绑定和人工封面保持；不改变其他媒体类型、旧 VIDEO 自动策略或手动选择来源。请求失败有界降级，取消及过期响应不能写回。此项明确替代下方历史版本“不增加自动回退”的限制，详见 D59。

Bangumi/TMDb 搜索共用完整可点击行，采用中性悬停、可见键盘焦点和不同的已绑定/绑定中/禁用状态。设置只移除主标题上方的小品牌文字，维护操作、缓存与路径控件局部统一，原配置语义不变。

按用户最新要求不拦截原生 F5，调试菜单将“重新加载”标注为 F5，并列出真实的返回与阅读器快捷键。既有 Ctrl+R 和菜单回调的设置保存及禁用保护保留；原生 F5 是 WebView 默认重载，不宣称它经过该回调保护。详见 `POLISH_AUTOTMDB_20261010.md`。

## 2026-10-10 全部资源书籍投影修复

全部资源对 SMART_MIXED 书库使用与资源库主页相同的已保存逻辑目录：独立书籍、系列和分类并列，不再把隐藏库根节点当作一张作品海报。四类书库均适用；普通文件夹模式的直属书籍按真实书籍身份分别展示，单本文件模式继续使用原独立 Node。全部资源穿透开关不改变书籍归属，也不跨库合并同名书籍。原识别、绑定、标签、封面和进度身份不变；单本打开内置 reader，系列和分类进入原智能资源库界面，返回恢复原集合状态。没有独立 Node 的书籍不借用父节点进行批量元数据修改。

书籍名称搜索返回各原始 ComicBook；真实文件夹/绑定/标签搜索继续存在，隐藏 Root 不充当书籍命中，单本 Node 与其同一书籍不重复列出。最近打开按视频 Node 与各书籍 ID 保留记录，不按共用父节点折叠多本书。书籍结果显示本书名称和封面，并直接打开原书；可读附件仍保留资源 FK，不因搜索或阅读变成独立作品。

## 2026-10-10 五项 UI 定向修复（当前 0.5.12 本地 RC）

TMDb 官方 Logo、英文声明、许可说明、官方链接和配置入口整块位于设置“浏览与扫描”的在线元数据区域，About 不重复展示；安全凭证 API、provider 和绑定保持。窗口栏语言/主题菜单以内侧右边缘锚定，并随窗口或触发器尺寸变化重新定位。普通 UI 的文本选区使用中性灰色，扫描成功、部分失败、失败分别保留可区分的语义色；阅读正文主题不受此选区样式影响。

所有新资源库均先选择识别方式，再点击“创建资源库”。初始无默认方式，未选择时点击创建只显示就地提示，不提交；视频保留 FOLDER/VIDEO_FILE 两个选项，书籍保留智能/文件夹/单本三个选项及不自动关联的原默认值。视频卡片使用与书籍一致的完整边框和间距。缓存路径组合控件修正内部高度，不改变配置行为。详见根目录 `UI_TARGETED_FIXES_20261010.md`；本轮没有新增迁移或修改扫描、阅读、海报管道。

## 智能书籍组织与电影提供方（Phase 3，经 2026-10-10 修订）

本地版本 0.5.12，尚未签名或发布。新建 COMIC/EBOOK/DOUJIN/ARTBOOK 提供“智能混合识别（推荐）”、文件夹识别和单本文件识别，初始不选中任何模式，明确选择后再创建。其中 SMART_MIXED 使用 FOLDER 来源索引和不可变组织策略；单本文件选项继续使用 VIDEO_FILE。旧库不转换；Bangumi 自动关联策略独立。Root 复用标准资源库标题、工具栏及海报网格，并列展示系列、独立书籍和分类目录；系列复用标准详情及原始书籍 ID，原目录通过既有路径或菜单访问，不另设一套目录主页。人工分类、系列、归入已有系列、独立和恢复自动只修改应用数据库。现有 Node 元数据仅在完整归属的实际锚点上复用，无 Node 锚点的组从真实 ComicBook 身份读取首册本地封面，复用现有缩略图管道；不复制成员身份、绑定、标签或收藏，也不伪造 Node。

影视 Root 的直属可读附件放在海报后的折叠“附属文档”，保留阅读和源路径，排除于影片项目计数；直属核心视频表保持原顺序。真人影视作品可主动在匹配弹窗中从默认 Bangumi 切换到 TMDB movie 搜索，共用关键词搜索、海报/标题/原名/日期结果和直接选择流程，不提供自动回退或电视剧支持。TMDB ID 与 Bangumi ID 分库存储；切换回来保留原 Bangumi 绑定，人工封面优先。凭证由原生输入窗口保存至 Windows Credential Manager，前端不接收密钥。设置“浏览与扫描”显示官方署名和 Logo，商业用途另需许可。

EPUB 的章节接口返回文本和有界本地插图引用；插图按需经原安全边界读取，不再将整章所有图片编码成一次大 IPC。单章超限保留目录和其他章节，文本、结构及插图错误分开提示。安全预算不整体提高，PDF/TXT/Kindle 阅读方式不变。

实际滚动容器内向上累计 8px 显示返回/面包屑，向下累计 24px 收起，到顶始终显示；保留布局占位及返回快照。语言地球与菜单触发器共享 hover 和点击范围。鼠标焦点保持中性，键盘焦点可见。标题栏真实“调试 → 重新加载”先 flush 设置，阅读器、模态及变更期间禁用；菜单快捷键标注随后由 D59 改为 F5，Ctrl+R 兼容回调保留。不提供无区别的“强制重新加载”。设置移除资源目录、播放器、浏览与扫描的三条分区说明，功能保留。

本文描述当前稳定产品行为。实现细节见 `PROJECT_CONTEXT.md`，不可静默改变的工程选择见 `DECISIONS.md`。

## 书籍与资源库（本地未发布）

M²Shelf 管理动画、真人电影/剧、漫画、电子书、同人本与设定集。添加资源库选择 ANIMATION / LIVE_ACTION / COMIC / EBOOK / DOUJIN / ARTBOOK，类别和识别模式创建后不可变；旧 VIDEO 库保留原有混合视频行为。所有类别均支持按文件夹或单个文件识别；书籍文件模式将每个 CBZ/PDF/EPUB/TXT/MOBI/AZW3 和图片集展示为独立作品，不调用外部阅读器。创建后自动扫描；若已有扫描则等结束后扫描新库。添加对话框不显示装饰图标或“资源库识别”小标题，路径导航使用普通文本，无独立位置徽标。

书籍库的直属图片作为一个阅读条目，CBZ、PDF、EPUB、TXT、MOBI、AZW3 文件分别作为一个阅读条目；普通 ZIP 仅作为其他资源，不识别为漫画或小说。保留原目录 Node，自然排序图片、PDF 页与 EPUB spine 章节；支持 JPG、JPEG、PNG、WebP、GIF、AVIF、BMP，大小写扩展名兼容。索引用扩展名筛选页面，读取按受支持的图片二进制签名识别实际格式，兼容 JPEG 内容误命名为 PNG 等情况；伪图片和原有尺寸/容量/路径限制仍拒绝。RAR、7Z 与普通 ZIP 暂不内置读取。MOBI6/KF8 支持范围和限制见本节下文。核心文件使用与视频一致的编号/名称/路径/信息/阅读操作表格，双击即可阅读；下方统一其他资源，同一文件不重复列为附件。重扫保留身份、标签、收藏、绑定与阅读记录，失败/取消保留未读取索引和失败基线。

MOBI6 和 KF8/AZW3 通过随程序附带的独立 libmobi 解析程序读取，支持 UTF-8/CP1252、未压缩/PalmDOC/HuffDic、NCX 目录、章节、本地图片/封面及基本文本样式。输出适配现有文字阅读器，复用翻页/滚动、所有文字与颜色设置、键盘、全屏、章节进度和书签；不执行原书脚本、网络、任意 CSS 或字体。DRM、字典、Print Replica、未知版本或超出预算的文件明确报错，不尝试解密。此支持不等于 Kindle 原书排版完整复刻。

所有 Root 的 PDF/EPUB/TXT/MOBI/AZW3/CBZ 文件统一列入阅读表并进入内置阅读器；旧附件索引无需重扫即可显示，统计与阅读表一致，同一来源路径不重复计数。独立图片附件也可内置打开，普通 ZIP/未知附件保留在其他资源并使用原有系统打开方式。阅读状态由原附件 ID 关联，保持来源 Node、路径、类别、索引、项目计数及返回导航；首次打开不把附件提升为独立作品。局部重扫不丢弃附件书签或进度；书籍库重扫将已支持附件转为正式书籍时保留原书 ID，包括单文件识别的 Node 归属转换。设定集是真实独立类别 ARTBOOK，复用书籍家族索引、筛选、搜索、详情、标签/收藏/最近打开。

自动关联关闭时，图片集使用自然顺序中首个有效索引图片，EPUB/MOBI/AZW3 优先合法内嵌封面；PDF 可提取首页直接嵌入的 JPEG 图片，当前不提供通用矢量 PDF 首页面栅格化，没有可用封面时正常占位。首图/内嵌封面始终经过既有源边界和图片预算，手工与现有缓存优先。

窗口栏直接从“文件”菜单开始，不显示左侧小 Logo；采用文件/显示/转至/调试/帮助五个紧凑菜单及右侧主题/语言快捷设置；调试仅提供受保护的真实重载，无第二层标题栏。菜单复用当前页面操作和既有设置 writer，保留读者退出/导航/禁用状态及原生拖动、双击、控制按钮。设置仅删除封面进度区底部重复分隔线，其他分组和功能不变。

书籍详情的顶部数量与正文阅读列表采用同一份所属内容，使用“项”计数，避免将话、番外和图片集都称为完整卷册。已展开为书籍的图片目录和中间格式目录不重复列入其他资源；其中的非核心附件仍保留。人工独立分类或不同绑定的子作品保持可打开的下级入口，并显示自己的可阅读数量。书籍列表、目录与附件从同一索引快照返回，打开详情不枚举媒体磁盘。文件的资源管理器按钮选中原文件，图片集按钮打开原目录；规范路径安全检查不改变交给 Windows Shell 的可识别路径表示。

漫画详情中已归入阅读列表的分卷图片目录和格式中间目录，不单独进入扫描后/现有资源自动匹配或后台封面尺寸生成、失败诊断及重试队列。系列、独立作品、人工独立分类和不同绑定的版本边界保留封面任务；既有绑定与手工封面不清除。同人本继续逐图片目录使用首图，电子书行为不变。设置和整理界面保留状态、操作及具体错误，删除重复的媒体只读或缓存实现说明；首次添加库的格式指引和有实际后果的确认提示保留。

全部资源混合展示并提供全部类型 / 动画 / 真人电影/剧 / 漫画 / 电子书 / 同人本 / 设定集筛选，与添加资源库的类别一致。兼容旧 VIDEO 库的已绑定条目按 Subject type 区分动画/影视，未绑定条目在两种视频筛选中均可访问。穿透开关仍只改变该页，书籍不参加视频来源聚合。详情使用共享封面与整理入口，单独展示核心书籍、页数/章节、进度及阅读按钮；本地搜索包含册名称，不以页文件名作为作品匹配证据。

## 2. 核心原则：源文件只读

Library Root 及其后代是用户资产，应用只读取，不得：

- 新建、移动、重命名或删除媒体目录中的文件；
- 修改媒体内容、目录结构或时间戳；
- 写入 NFO、海报、字幕、数据库或临时文件；
- 把应用标签、收藏夹或绑定信息写回媒体目录。

下列信息只属于应用数据库或应用缓存：

- 扫描索引和人工显示名称；
- 人工分类与忽略状态；
- Bangumi 绑定和多语言标题；
- 封面缓存路径与错误状态；
- 用户标签、收藏夹、最近打开、漫画阅读进度与书签；
- 界面、播放器、缓存、窗口和排序设置。

删除资源库只删除 M²Shelf 的索引，不删除磁盘内容。

## 3. 资源库与扫描

### 3.1 Library Root

用户可以添加多个本地或 Windows 可访问的映射目录。添加时选择动画、真人电影/剧、漫画或电子书；两类视频选择“按文件夹识别”或“按视频文件识别”，两类书籍选择“按文件夹识别”或“按单个文件识别”。旧 VIDEO 库保留混合视频范围，已有 Root 缺失识别模式时默认按文件夹识别。选择保存在该 Root 中并用于后续扫描，不允许直接切换已有 Root 的类别或识别方式，以免改变 Node 路径身份并级联丢失应用元数据。每个 Root 有独立显示名称、路径和最近扫描时间；修改显示名称不改变真实目录名。新增 Root 必须先解析为真实规范路径，并按 Windows 不区分大小写、按路径组件比较的语义拒绝与已有 Root 相等、互为上级或互为下级的目录；文字前缀相同但组件不同的同级目录不受影响。旧数据库若已存在重叠 Root，扫描入口必须拒绝继续扫描，避免 Node 在 Root 之间改变归属并级联丢失应用元数据。

### 3.2 扫描行为

默认每次启动在设置和扫描事件监听准备好后，静默检查已添加的资源库一次。自动检查不显示进度条或完成/失败提示；没有变化时不刷新列表、详情或滚动位置，发现新作品、新集数、删除或文件信息变化后才重载当前视图。设置中的“启动时自动更新资源库”可关闭此行为。手动扫描保留进度、停止与结果反馈。首次尚未添加资源库、已有扫描或正在处理更新恢复通知时不重复启动。不可访问的目录保留已有索引。

为发现软件关闭期间和深层目录的变化，仍需只读枚举目录项，与上次名称、类型、大小和修改时间快照比对，不读取媒体内容。文件夹模式跳过未变化子树的重复索引及匹配；文件模式也跳过未变化的物理子目录，保留已有视频、附件和蓝光条目。首次检查、扫描设置/隐藏状态变化或手动扫描后建立新基线；读取失败或取消时不推进基线。此功能更新本地索引，不下载视频。

扫描必须：

- 递归读取任意深度目录；
- 支持 Unicode、空格和方括号路径；
- 每次进入目录或读取文件前确认规范化路径仍位于当前 Library Root 内，跳过链接和越界重解析路径；
- 按配置的视频扩展名索引视频；
- 单独索引字幕、图片、音频、文档、压缩包、字体、播放列表和其他附件；
- 识别常见 BDMV 结构，避免技术目录污染作品层级；
- 可报告进度、取消和错误；
- 在完成后清理本次范围内已经不存在的旧索引；
- 保留人工类型、显示名称、绑定、标签和收藏夹。

按文件夹识别沿用既有目录树、视频分布分类和局部目录扫描。按视频文件识别仍递归只读遍历，但把每个普通视频文件扁平创建为一个独立作品 Node，使用真实文件路径作为稳定身份、去扩展名文件名作为初始显示名，并分别参与标题/封面绑定；非视频附件只作为资源索引，不生成作品。BDMV 结构在该模式下仍聚合成一个作品而不是把 `STREAM` 片段拆成大量卡片。对文件作品发起局部重扫时，后端升级为该 Root 的完整安全扫描。

完整扫描可以为未绑定且合格的 Node 触发自动匹配。显式“匹配现有资源”只处理当前索引，不重新遍历磁盘。

### 3.3 分类

底层分类仍以视频分布为依据：

- `WORK` / `AUTO_WORK`：当前目录直接承载作品视频；
- `CONTAINER`：主要聚合下级作品，界面称“系列”；
- `MIXED`：同时包含直接视频和下级媒体分支，界面归入“其他资源”；
- `IGNORED`：用户明确忽略。

自动判断使用直接视频数、子媒体分支和总视频数。人工可设为作品、系列、其他资源、忽略或恢复自动判断；重新扫描不得覆盖人工选择。

SP、OVA、Extras 等补充目录不会仅因存在而把父目录错误拆散。非视频附件本身不能让目录成为作品或 Bangumi 候选。

## 4. 浏览、搜索与详情

### 4.1 浏览入口

侧栏包含：

- 全部资源：默认保留原目录卡片；设置中开启“全部资源穿透显示”后，使用跨层级作品平铺与来源聚合视图；
- 搜索：跨索引搜索；
- 最近打开：合并视频成功播放和漫画实际阅读时间，按最近时间倒序；
- 收藏夹：一层命名集合；
- 每个 Library Root：文件夹识别模式按真实目录层级浏览，视频文件识别模式显示扁平的独立视频作品；
- 设置。

全部资源和各集合支持海报网格或紧凑列表、标题/加入时间/更新时间/观看时间排序、筛选及编辑模式。

作品库仅展平具有所属视频的 WORK/AUTO_WORK，普通自动匹配复用同一集合；MIXED/CONTAINER 不因直属视频成为作品候选。忽略子树排除，人工类型和独立绑定保持边界。系列负责目录组织，作品库负责跨目录平铺及来源聚合。相同 Bangumi Subject 类型与 ID 的来源合并成一张作品卡片，不同季度对应的不同条目分别展示。未绑定的视频文件作品，仅在同一物理目录内按清洗标题、季度、年份与版本分组；证据不足时独立显示。未绑定的文件夹来源不会仅凭同名跨目录合并，可绑定相同 Bangumi 条目进行归并。已有 Root 的识别模式不变；同一目录混放多部作品时，应使用“按视频文件识别”的资源库。

作品详情汇总该作品各来源的直接视频、附件和子资源，保留每个视频的真实路径、播放与定位动作，并提供可展开的来源列表。作品视图的编辑模式展开原始来源，改名、分类、隐藏、标签和收藏作用于明确的源 Node，Bangumi 绑定、改绑、清除及自动封面重试按整组来源执行；分组不合并数据库行、不重命名源文件。切换展示方式和从详情返回时保留相应导航状态。

### 4.2 搜索

“全部资源穿透显示”位于设置的“浏览与扫描”，新库及未保存此设置的旧库均默认关闭。选择立即生效、自动保存并在重启后恢复。该开关只选择全部资源页面的原目录视图或作品聚合视图，不切换 Root 识别模式，不改变扫描、分类、绑定或详情的视频展示规则，也不修改媒体源。页面不再提供独立的展示方式下拉菜单，避免两处设置不一致；导航历史不会覆盖该持久选择。

本地搜索可匹配：

- 数据库显示名称和真实文件夹名称；
- Bangumi 主标题及中、英、日、韩标题；
- 用户标签；
- 已索引视频文件名。

结果使用当前封面和本地化显示标题。搜索失败不得触发媒体目录写入。

### 4.3 详情页

打开新详情时滚动到顶部。详情展示封面、标题、Bangumi 信息、视频列表和附件列表。

- 视频按自然顺序排列，双击调用外部播放器；
- 附件按资源类型展示，可由 Windows 默认关联程序打开；
- 文件定位必须在资源管理器中选中准确文件；
- 打开系列时继续浏览其子节点；
- 返回列表时，在已有快照的情况下恢复浏览位置和控件状态。

## 5. Bangumi 与标题

### 5.1 网络边界

Bangumi 功能可在设置中关闭。启用时仅访问批准的 Bangumi 官方主机，使用 TLS 校验、系统代理、明确超时和有界请求；搜索与详情 JSON 响应均有独立大小上限，瞬时网络错误、HTTP 429 或服务器错误最多进行一次有界重试，并把数字 `Retry-After` 截断到短等待。本地浏览不依赖该网络；一次提供方级搜索失败会终止本轮剩余在线匹配，避免离线或限流时对每个 Node 重复等待。

### 5.2 关键词提取

匹配证据可来自：

- 当前目录名；
- 代表性或高频视频文件名；
- 有帮助的父目录标题；
- 季度、年份和作品类型线索。

提取器应去除字幕组、编码、分辨率、校验码和集数等噪声，同时保留原始标题、拉丁转写、季度与续作信息。`S2`、`Season 2`、日文或中文季信息必须作为结构化证据，而不是随意并入作品主名。对包含年份或技术发布段的多点分隔名称（例如 `Movie.Title.2020.1080p`），点号按发布分隔符处理；普通具有语义的点号标题不能被无条件改写。

影视发行名中的全角方括号发布站、字幕、HDR、音轨等技术段按同一噪声规则处理；相邻出现的中文、日文或韩文标题与拉丁标题保留原组合证据，同时拆成独立的安全候选，在既有最多三查询与直接匹配门槛内提高召回。通用父目录名（如“电影 / 影视 / Movies”）不得占用搜索查询。用户修改过显示名时，真实文件夹或文件标题仍作为独立候选保留，使自动匹配与手动搜索不会因显示名不同而失去同一条有效证据。

电影或真人影视在目录名缺少年份时，可从视频文件名补取唯一占优的发行年份；分辨率中的四位数字不得作为年份，标题本身的四位数字在后方存在真实发行年份时必须保留。纯四位数字片名仅在视频文件名同时提供独立发行年份时进入自动搜索，单个无独立年份的数字文件名保持保守不匹配。官方查询仍最多三次，只有有效主标题且存在空余查询位时才追加“作品名 + 年份”，不得挤掉独立原名、译名或父目录证据。

### 5.3 自动匹配

普通自动匹配必须同时满足：

- Node 属于共享逻辑归属计算出的有视频 WORK/AUTO_WORK 来源，且尚未绑定；
- 最多使用三个官方搜索关键词；
- 多个查询的候选按提供方排名公平合并；
- 高置信结果也补全胜出项的详情以保存官方别称；其余结果最多读取初步评分最高的五个候选详情，仍遵守整轮预算；
- 单次匹配运行最多启动 256 个新的 Subject 详情请求，重复 Subject 复用本轮缓存且不重复计数；预算允许时至少为每个尚未处理的 Node 保留一次未缓存详情机会，避免前部项目耗尽整轮预算，预算耗尽后仍可基于有界搜索元数据评分；
- 新动画库只接受 Bangumi type 2，真人电影/剧库只接受 type 6，漫画/电子书库只接受 type 1；旧 VIDEO 库保留 type 2/6，禁止跨库类型绑定；
- 最高候选达到配置的直接绑定阈值，且多语言标题相似度、季、强年份、版本和类型没有强冲突；
- 主关键词送交 Bangumi 后返回的第一个合格条目可提升到直接绑定门槛，但仍不能绕过季、强年份、版本或类型保护；
- 系列与其他资源不进入普通自动搜索；系列保留手动绑定和已有绑定，候选同分时以 Bangumi 提供方排名稳定决胜。

不再保留“待确认”区间，也不以第一、第二候选的分差阻止一个已经达到直接门槛且没有硬冲突的最高候选写入 `metadata_bindings`；未达到门槛或存在硬冲突的结果仍记为未匹配。普通自动流程不得替换已有绑定或手工封面。已有绑定的自动封面若被清理或缓存文件丢失，普通扫描或“匹配现有资源”只按已保存的 Subject 与官方封面 URL 恢复封面，不重新搜索或改绑。未明确独立分类或绑定的 SP、OVA、Extras 等补充目录不单独参与自动匹配，其视频归所属逻辑作品；仍可手动绑定并建立独立边界。

只有用户在编辑模式中明确执行“重新匹配所选”时，才允许在同一直接门槛和硬冲突规则下替换已有 Bangumi 绑定；手工封面仍不得被覆盖。

### 5.4 手动纠正与失败

用户可以手动搜索、选择、清除或重试绑定。封面下载失败时：

- 有效绑定必须保留；
- 记录并展示可理解的失败状态；
- 允许显式重试；
- 不回退为错误的其他条目。

用户明确选择 Bangumi 条目时，应用可以把该 Node 自身经过清洗的显示名、真实文件夹或文件标题、代表性视频标题保存为本地确认别名；父目录上下文和媒体路径不作为别名，季数与年份等有效限定信息不得在入库时再次被清除。后续 Node 具有相同译名时，按当前证据优先级选择第一个有历史观察的别名，且该规范化别名的全部人工观察必须一致指向同一、且属于该 Root 允许类型的 Subject；如果这个高优先级别名曾指向不同 Subject，则视为歧义并回退到普通 Bangumi 搜索。唯一映射的 Subject 优先读取官方详情，但普通的最多三次官方搜索仍作为别名过期、详情失败或硬冲突时的回退候选。确认别名只提供标题精确信号，不能掩盖官方季数、年份或版本冲突。自动绑定不会生成别名；清除或替换来源 Node 的绑定、或删除该 Node 时，一并移除其观察。此数据只保存在 M²Shelf SQLite，不写入媒体目录，也不发送给新的第三方标题服务。

动画与真人影视共用同一直接绑定阈值以及年份、季、版本和作品类型冲突规则。绑定会保存 Bangumi Subject 类型；旧绑定升级后按历史行为默认 type 2，因此真人影视在重启后也能按正确类型重新读取详情并重试封面。

### 5.5 多语言标题

支持 `zh-CN`、`en-US`、`ja-JP`、`ko-KR`。绑定标题选择顺序为：

1. 当前语言标题；
2. 中文标题；
3. Bangumi 主标题；
4. 数据库 `display_name`；
5. 真实 `folder_name`。

标题本地化只影响显示层，不改变路径。系列后缀也是本地化展示，不写入源目录。

## 6. 封面缓存

封面来源包括 Bangumi 下载、本地手工选择和占位图。下载或选择的文件只能写入应用拥有的缓存。

手工封面与 Bangumi 下载在写入前都必须限制字节数，校验 JPG、PNG、WEBP 的真实格式和合理像素尺寸，并通过缓存目录内的唯一临时文件原子提交。旧缓存读取时重复执行像素尺寸校验，避免小体积但声明超大像素的图片进入 WebView 解码；下载或替换失败不得先删除已有有效封面。

用户可以修改活动封面缓存目录。新目录必须：

- 不位于任何 Library Root 内；
- 经过路径有效性检查；
- 在重启后保持；
- 不改变数据库中已有 Bangumi 绑定。

切换目录后不自动迁移或删除旧缓存，旧封面仍可按数据库路径读取。清理缓存只能删除应用确认拥有的活动缓存文件，不能递归删除无关用户文件。清理与封面读取、下载、手工复制及其数据库路径更新通过应用内屏障协调；后台扫描或自动匹配仍在运行时拒绝清理，不能删除进行中的临时文件或清空刚提交的封面路径。

主列表、搜索结果和详情页共用单个图片元素，直接显示后台生成的本地缩略图。Rust 提前完成高质量缩小，前端不再生成 ImageBitmap 或 Canvas，不在滚动/停滚时从预览图换成另一幅画面。图片框尺寸固定，裁切/完整显示方式在首次显示前确定；已经显示的图片不会因离屏或请求保留区变化而重新裁切、换元素。明显横版或近方形素材在竖框内完整显示，普通竖版铺满。列表以实际内容滚动容器为观察根，提前读取，IPC 最多四路；精确修订的缩略图 data URL 跨页面保留在 128 项/约 32 MiB LRU，已排队请求允许完成，旧修订不能回流。共享 64 项目标只控制保护区外的请求保留，缓存容量淘汰才通知释放相应图片引用。滚动容器预留稳定滚动条槽，避免内容增减改变网格宽度。

应用封面缓存额外保存 256、384、512、768 像素宽的持久缩略图，等比缩小、保留透明度及方向/色彩配置，不放大小原图。界面按实际海报宽度乘显示 DPR（上限 2）向上选择最近档位，窗口缩放和跨屏移动时自动更新；升级档位期间保留原预览。普通不透明缩略图使用质量 95 的 JPEG，透明图使用无损 WebP，原图不重新编码。后台完成状态和中断游标保存到应用数据库，重启直接恢复完成状态或从中断位置续跑，不重新全量遍历。扫描完成以及封面更新后，由单个后台任务检查并补齐缺失档位，不阻塞扫描完成。缓存命中只读取小缩略图，缺失或损坏时按需重建，无法写缓存时回退到已有封面。原封面身份/修改时间或索引首图修订变化会使旧缩略图失效；派生文件限 4096 项/512 MiB；后台达到上限后记录暂缓，不淘汰已生成封面来补其他档位，前台按需读取仍采用最近使用淘汰。失败原因持久保存，可在设置查看并显式重试失败项；任务级错误从已保存位置继续。编码升级仅替换严格识别的旧版派生文件。清封面缓存时一并清理派生文件、进度和错误，始终不写入媒体资源库。浏览直接使用选中档位的成品图片，不再进行前台重采样；磁盘缓存仍需正常读取和首次图片解码。

设置的“索引与封面缓存”显示“适配封面”后台进度，包括本轮状态、已处理/总封面数和生成失败数；处理计数包含已检查的缓存命中，完成表示本轮检查结束，磁盘配额仍会淘汰旧派生文件。离开设置后继续生成，再次进入可读取本进程保留的状态。手动扫描或匹配完成时提示会后台准备适配尺寸，并指引到此处查看；启动自动检查保留安静策略。设置项先显示并可编辑，缓存大小统计和生成进度随后独立补上，不阻塞首次显示或自动保存。

## 7. 本地整理功能

### 7.1 用户标签

标签是规范化名称与 Node 的多对多关系。支持新增、重命名、删除、单项或批量赋予，并可用于筛选和搜索。标签只存在于应用数据库，与“作品 / 系列 / 其他资源”系统标签在视觉上保持区分。

批量操作必须先验证完整 Node 集，再使用事务提交；失败时不得留下部分修改。

### 7.2 收藏夹

收藏夹是侧栏下的一层命名集合：

- 一个 Node 可加入多个收藏夹；
- 支持创建、重命名、删除和批量加入/移出；
- 跨资源库使用；
- 删除收藏夹只删除集合及成员关系；
- 重新扫描保留成员关系，Node 正常删除时由外键清理。

### 7.3 最近打开

视频仅在外部播放器进程成功启动后记录对应 Node；漫画仅在索引页面成功解码并可见后记录册和页码。按 Node 合并最近时间倒序，漫画可从最近读过的册续读。视频表和兼容 DTO 名称保留，漫画进度/书签为独立表。不得读取播放器历史、猜测状态或写入媒体文件。

## 8. 播放器与 Windows 集成

产品文案统一称“播放器”。兼容设置键 `mpv_path` 可以保留，mpv 只作为示例。

- 播放器路径由用户配置并可测试；
- mpv、VLC、PotPlayer、MPC-HC/BE 等播放器统一以唯一的媒体文件路径参数启动，不向通用播放器插入 mpv 专属参数；
- 媒体路径作为原生进程的字面参数传递，不经过 shell 拼接；
- 普通附件使用 Windows 默认关联程序；
- “在资源管理器中显示”应选择准确文件；
- 应支持 Unicode、空格和特殊字符路径。

## 9. 设置、语言与主题

设置页修改自动保存，重启后恢复。不再设置重复“只读”信息的专属底栏；全局状态栏继续提示媒体源只读。标题旁在实际保存时显示进行中状态，成功后显示约 3 秒的自动保存回执，首次读取设置与保存失败不显示成功回执；失败反馈和持久化回滚保持原行为。主要设置包括：

- 外部播放器路径；
- 默认网格或列表模式；
- 视频扩展名；
- 是否启用 Bangumi；
- 界面语言；
- 主题；
- 活动封面缓存目录。

用户可见文案进入类型化 i18n 资源，支持简体中文、English、日本語、한국어。界面使用 Windows/system 字体栈，不捆绑字体文件。

主题使用语义 CSS 变量，提供 `system`、`light` 和 `dark`。跟随系统模式应在应用打开期间响应系统变化；暗色模式不是简单反色。

## 10. 导航与窗口状态

打开新详情时滚动位置为零。应用返回、`Alt+Left` 或 WebView 历史在有快照时恢复先前的滚动、筛选、排序、网格/列表和浏览层级。

侧栏目的地分别保留会话内快照：全部资源、搜索、最近打开、收藏夹及每个资源库。资源库和收藏夹恢复时必须重新装载当前数据库行，不能用旧快照覆盖扫描或元数据修改后的新数据。

全部资源、资源库浏览和收藏夹分别把最后排序写入 SQLite `settings`；它们与设置页整组 `AppSettings` 分离。主窗口关闭时保存一次有效尺寸。启动时窗口先以隐藏状态创建，在当前显示器范围内恢复尺寸并准备好已保存主题的首屏后才显示，不能先暴露默认尺寸或白色 WebView 再跳变。

## 11. 软件更新

### 11.1 检查与提示

M²Shelf 使用固定的 GitHub Release `latest.json` 检查稳定版更新。版本号只接受规范的 `major.minor.patch` SemVer；预发布、带 build metadata、相同版本和降级一律拒绝。如果固定地址仅因 GitHub 最新公开 Release 尚未携带清单而返回 404，且最终地址能严格证明是本仓库准确的 `v{version}/latest.json`，该 tag 只可在不高于当前版本时用于返回“已是最新”；更高版本缺少受签名清单仍必须失败，tag 本身不能授权下载或安装。

设置中的“启动后自动检查更新”默认只检查并显示四语言提示与对应语言的更新说明，不得自动下载或安装。设置页同时提供同层级的手动检查按钮；无更新或检查失败使用简短提示，只有发现经过清单验证的新版本时才打开更新详情。

用户可以手动检查、明确开始下载，并在下载完成后再次确认安装。检查、下载和安装同一时间各只允许一个操作；网络或校验失败不得改变当前安装。

### 11.2 发布和完整性契约

稳定更新只接受 M²Shelf 官方 GitHub Release 中的固定版本化 Windows x64 资产：

- `M2Shelf-Portable-{version}-x64.zip`；
- `M2Shelf-Setup-{version}-x64.exe`（NSIS）。

清单中的 URL、文件名、平台、长度、SHA-256 和 Ed25519 签名必须相互匹配。签名消息同时绑定应用 ID、版本、平台、长度和摘要；客户端在下载完成及执行前重新验证，不能仅信任清单中自带的哈希。请求限于批准的 GitHub HTTPS 主机、有界大小、超时和重定向范围。

生产私钥只在开发工具和 Agent 均不可执行命令的独立离线环境使用，绝不进入仓库、GitHub Actions、Release、日志或文档；开发账号的 CurrentUser DPAPI 只可用于流程测试。分发版 updater 不提供密钥生成命令；生产信任根仅通过不参与打包的离线初始化工具建立，该工具将 seed 直接封装为 CurrentUser DPAPI 密文，并只允许公钥文件返回源码。CI 只生成无签名候选，其普通 JSON provenance 仅用于核对，生产签名还必须验证受信 attestation 或隔离环境独立构建得到的候选摘要，并核对 manifest generator、helper 指纹及嵌入身份。发布脚本先验证、建立草稿，再要求远端资产名称、大小和 SHA-256 digest 精确一致后发布。已发布版本视为不可变，不在原 Release 上替换资产。

### 11.3 安装方式

NSIS 版只执行通过最终验证的对应安装器。Portable 版使用同目录随包分发的 `M2ShelfUpdater.exe` 完成事务式就地替换：

1. 主程序确认安装目录是 Portable、更新缓存及安装目录均不与任何 Library Root 重叠，复制可信 helper，取得 SQLite 单写入屏障后建立一致快照并记录其长度/SHA-256，再生成受路径约束的事务；屏障保留到旧进程退出；
2. helper 全程持有独立 Windows 更新互斥锁，在旧程序仍运行时锁定、复验并密封下载包，写入原子 helper-ready 回执；主程序只有收到正确回执后才退出，普通手动启动必须等待 helper 完成；只有规范事务 ID 能通过当前可执行文件、目标版本、精确活动事务与 `Launched` 阶段的完整认证时，新版子进程才可绕过等待；
3. helper 等待旧进程退出，严格解包到同卷暂存区，验证文件集合、Portable 标记及目标版本；
4. 逐项备份和原子替换，`M2Shelf.exe` 最后替换，再启动新版本；
5. 新版本必须提交完全相同版本的原子健康回执，并在回执后持续存活完整三秒；helper 随后先原子记录保留事务材料的终态 `Completed`，完成受校验清理后才清除保留标记。启动时若发现该终态清理中断，应继续清理，而不是把已成功更新误报为需要恢复。

任一步失败都先有界确认新进程已终止，再按逆序恢复程序文件。SQLite 回滚前必须重新验证快照长度、SHA-256 和 `PRAGMA quick_check`，完整预检 WAL/SHM 后再隔离并原子替换主数据库；无法安全完成时保持当前数据库不变并标记需要人工恢复。helper 异常终止留下的严格可识别非终态事务也标记人工恢复，不执行缺少可靠日志的猜测式自动回滚。自动回滚与人工恢复提示均以本地化对话框持久显示，只有用户明确确认后才清理通知。更新缓存及其版本/事务目录必须是应用目录下经过真实路径与重解析点校验的普通目录；清理只处理严格识别的更新器文件，不穿过链接递归删除。更新缓存、暂存、备份和回执绝不进入媒体目录。

`v0.5.8` 仅保留为 CI 失败的不可变历史 tag，`v0.5.9` 仅保留为最终修复前创建且未公开的不可变历史 tag，`v0.5.10` 仅保留为最终匹配修复和生产密钥轮换前创建的不可变未发布 tag；三者都没有 Release、资产或 `latest.json`，不得移动、复用或作为更新授权。`0.5.11` 被指定为首个包含更新器的新信任根引导版本，只有完成受信 attestation、隔离签名与正式 GitHub Release 后才能描述为已发布。`0.5.7` 及更早版本，以及任何私下分发的旧公钥测试包，都必须由用户手动安装 `0.5.11` 一次，之后才能使用内置稳定更新。

## 12. 数据兼容与安全

- 所有 SQL 在 Rust 中执行；WebView 不直接访问数据库；
- 数据库改变使用增量 migration，不删除已有用户数据；
- 删除与批量写操作使用外键和事务维持一致性；
- 网络、文件选择和进程权限保持最小范围；
- 不提交密钥、令牌、个人文件路径、真实媒体索引、聊天记录或一次性需求全文；
- 公开构建必须检查产物中不存在构建者路径；
- Logo 使用仓库指定母版并按完整画布等比生成各尺寸，不重新设计或修改母版。

## 13. 当前非目标

当前版本不负责：

- 内置播放、在线视频或转码；
- 媒体服务器和远程串流；
- 账号、云同步和多人共享；
- 自动字幕、播放进度或续播；
- 自动移动、重命名或整理源文件；
- Bangumi 账号收藏、评分或观看状态同步。
- 静默下载、静默安装、测试版通道或自动降级。

## 14. MVP 验收标准

一个发布候选至少满足：

1. 可添加、扫描和移除多个 Library Root，媒体目录内容不发生变化；
2. Work / Container / Mixed 分类与人工覆盖在重扫后保持；
3. 全部资源、目录、搜索、最近观看和收藏夹可正常浏览；
4. 视频、非视频附件、打开和精确定位功能可用；
5. Bangumi 自动匹配把达到直接门槛且没有硬冲突的最高候选写入绑定，不产生待确认状态；手动纠错、本地确认别名复用和封面重试可用；
6. 四种语言及三种主题均可切换并持久化；
7. 标签、收藏夹、最近观看、窗口尺寸和排序均按规格保存；
8. 老数据库通过增量 migration 升级且不丢失应用元数据；
9. TypeScript、前端构建、项目验证、Rust 格式、测试和 Clippy 全部通过；
10. Windows NSIS 与 Portable 由正式脚本生成，通过版本、图标、隐私、校验和与启动检查；
11. 更新检查拒绝非规范、非更高或非固定 GitHub 资产，下载包通过 SHA-256 与 Ed25519 验证；
12. Portable 更新通过 helper-ready、SQLite 备份、主程序最后替换、精确版本健康回执和完整三秒存活观察，并在故障注入下可自动回滚；
13. GitHub Actions 产物不含生产私钥或签名，线下签名及发布脚本可对来源、签名和远端资产集合执行 fail-closed 验证。

## 15. 逻辑归属、详情与升级扫描

FOLDER 模式支持完整编号 CD1、CD 01、Disc 1、Disk 1、BD1、DVD1、Vol.1、Volume 1 分卷。可用父标题、所有媒体分支能归为分卷或补充内容、无明确视频标题/季度/年份及绑定冲突时，外层即使无直属视频也成为 AUTO_WORK。普通独立媒体分支、人工独立分类及不同绑定保留边界。CDs、Scans、字幕不生成作品；只有 SP/OVA 没有主体证据时不提升父目录。VIDEO_FILE 模式不套用此合并。升级仅重算已有索引，不强制首次全盘扫描；可疑历史分卷绑定保留并提示核对。

普通及聚合详情上方保留直属视频，在“作品中的其他资源”递归平铺所属子目录视频，按相对目录、文件名自然排序，去重原始文件 ID，区分同名路径和多来源。独立子作品仍可进入并停止递归，隐藏子树跳过，BDMV 技术目录不重复。附件和目录入口置于视频之后，已展开目录有说明，来源区在底部。打开详情只查询 SQLite。统计、观看及更新时间按归属计算。

整组操作必须提交来源集与分组快照，后端在事务内核验，网络期间删除、拆组或改绑导致过期时整组拒绝并刷新。Subject 详情和封面复用一次，手工封面受保护。封面失败保留完整绑定并提示；重试只恢复需要的来源。解除绑定可能按剩余本地证据拆组。

作品级操作不套用普通批量编辑的 500 项限制，必须验证完整当前分组并在一个事务提交。快照覆盖来源身份、分组证据、绑定和封面状态、所属文件及独立边界；观看记录、标签和无关更新时间不使操作过期。绑定事务返回封面阶段快照，不在提交后重新采集。损坏缓存与前端解码失败可明确重试，失败来源 ID 不得扩大操作范围。列表、目录浏览与详情的多次查询共享 SQLite 读取快照；单条分类修改和祖先重算共同提交或回滚。目录被隐藏或移除后拒绝旧详情读取，刷新后返回资源库；隐藏管理仍可读取恢复数据。

设置的“关于”仅保留“关注作者”下的森下Undermori · Bilibili 外链（移除 X 指引），以及独立的“特别感谢”信息行；标签与 Juvenile_A 分列对齐，使用与版本、架构一致的布局，不拼接成拥挤页脚。不重复显示原作者、维护角色或 Created by。四语言同步。构建日期由构建脚本提供；开发构建未提供日期时显示不可用。当前本地构建保留 0.5.11，正式发布安排独立进行。

历史别称每次应用运行最多尝试32个不同 Subject，失败也占预算，刷新与重复 IPC 不重置，settings 轮换游标防止失败条目阻塞后续项，成功空别称也完成。提供方整体故障结束本轮，关闭功能停止新请求。

每库记录最后自动尝试、最后完整成功、成功/部分失败/失败/已取消和错误摘要，在设置中查看与重试，失败库侧栏有轻量提示。无变化时仅刷新健康；离线、深层读取失败或取消保留未成功观察的旧索引和失败库基线，各库独立结算。新库启动更新默认开启，旧库缺少设置时默认关闭，已有选择保留。首次开启执行真实更新后才保存基线，并告知可能完整枚举目录。此规则替代此前无条件默认开启的描述。
