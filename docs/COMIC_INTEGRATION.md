# 漫画 / 电子书：本地验收

当前工作树已接入漫画库与内置阅读器，保留现有未发布 UI。版本号仍为 0.5.11；本轮不提交、不推送、不签名、不修改已公开 Release 或生产信任根。

本轮更新了漫画匹配、阅读与窗口展示，新增电子书与分开的动画/真人影视库，支持 PDF/EPUB。最终本地测试包位置与校验摘要在文末；它是未签名测试包，不能作为 updater 发布资产。原正式包和 SHA-256 边车逐字节保留。

## 使用

1. 添加资源库，选择动画、真人电影/剧、漫画或电子书，再选择按文件夹或单个文件识别。已有库保持原模式及原有匹配范围；不原地转换识别方式。
2. 创建后自动扫描；已有扫描会先结束再扫描新库。扫描图片目录、CBZ、PDF 或 EPUB。普通 ZIP 只列入其他资源。直属图片为一册，每个支持文件为一册；文件夹模式保留层级，单个文件模式将书籍文件和图片集作为独立作品。
3. 打开作品，在与视频一致的核心文件表格选择开始阅读或继续阅读，附件和子目录在下面的其他资源区只显示一次。漫画支持单 / 双页、右到左 / 左到右、连续滚动 / Webtoon、适应页面 / 宽度 / 原始大小、缩放、宽页独立与全屏；PDF 默认以宽高共同适应整页。
4. 阅读设置调整本次打开的展示；设置页保存下次默认值。默认 LTR、双页、分页、宽页独立，保留之前保存的 RTL。上下控制条常驻且不覆盖正文。卷册行支持双击或键盘阅读。
5. 底部书签按钮或 B 保存当前位置，选中显示品牌色实心；旁边的下拉框跳转已保存页或章节，上方不再显示重复标记。所有阅读器用统一设置图标打开调整面板。方向键、PageUp / PageDown / Space 翻页，Home / End 到首尾，F 全屏，Esc 退出全屏或返回。输入框保留自己的键盘行为。
6. 最近打开合并视频播放和书籍实际阅读，点击书籍直接续读。全部资源可按视频 / 漫画 / 电子书筛选，标签、收藏和整理菜单继续可用。

## 边界

- 所有媒体源只读；不移动、重命名、删改、解压、生成 ComicInfo 或写入进度。应用 SQLite 保存册、页面、阅读进度和书签。
- 图片：JPG/JPEG、PNG、WebP、GIF、AVIF、BMP。PDF 按页绘制；EPUB 按章节展示文字和本地插图，不执行书内脚本、加载网络资源或原书 CSS，不承诺复杂版式保真。普通 ZIP、RAR、7Z、MOBI 和加密书籍不作为内置可读书；损坏/变化时提示重新扫描。
- Bangumi 查询与写入按 Root 隔离：新动画 type 2、真人影视 type 6、漫画/电子书 type 1；旧 VIDEO 保留 type 2/6。保留卷号与 `:re` 的具体版本证据，不作为动画季度；仅使用目录和册名，不使用页名作为作品证据。
- 上限：64 MiB/图片、10,000 页/册、20,000 项/包、16 MiB 中央目录。PDF 索引独立支持 ≤512 MiB，原生索引时解析文档；阅读时以 ≤2 MiB 二进制分段按需传输，避免整本进入 WebView。预检归档中央目录后才分配元数据，图片按需读取。
- 原生最多 4 个读取，前端最多 2 个；Blob/解码估计总缓存最多 12 页且 128 MiB。滚动虚拟窗口最多 12 个页面占位，保留尺寸并撤销淘汰 URL。
- 阅读进度只在已解码页面可见时更新，预加载不计为阅读；700ms 节流与退出刷新，按册修订验证，避免重扫后的旧页码提交。
- Root 类型和识别模式不可原地切换。migrations 0015–0020 为增量升级，旧库默认 VIDEO，保留绑定、设置、标签和收藏；0018 增加 document_format，0019 增加书籍子类型和视频匹配范围，0020 开放书籍单文件模式并统一模式不可变，不重建 Root 表。测试前建议备份应用数据库；本轮没有读取或修改真实用户数据库。

## 后续修复

添加库弹窗标题正常横排；集合上层操作右对齐，类型筛选器复用标签控件样式，宽窗口设置内容居中，作者链接加粗。详情从数据库平铺所属下层书籍，保留独立/忽略边界，格式提示固定在册数上方；每行支持定位源文件或打开图片目录。EPUB 操作使用章节用词，共享错误与历史使用书籍文案，覆盖四语言。

EPUB 本地兼容普通 XHTML DOCTYPE、UTF-16，保留安全文本语义及行内格式，插图适应高度、正文限制行宽，缩放保留位置。参考 [Foliate-js](https://github.com/johnfactotum/foliate-js) 的局部资源解析与 [epub.js](https://github.com/futurepress/epub.js) 的重排思路，自行实现有限安全块，没有引入原书 CSS/脚本执行。排查并修复了新库遇到已有扫描被跳过、缩放重读章节、PDF 初始化错误被 effect 清空，以及设置页误将书籍识别称为视频识别的问题。

## 本轮注意事项

漫画匹配失败的原因为：早期无图片的 ZIP 让整个库标记 PARTIAL 后跳过匹配，漫画系列没有进入自动候选，泛化的父合集标题又覆盖子卷/RE 证据。现普通 ZIP 仅为附件，部分失败库只匹配有效索引，卷/RE 保留并阻止绑定冲突结果；不会在普通自动路径替换已有绑定或手动封面。运行新版后重新扫描漫画/电子书库，再对历史错误绑定使用显式“重新匹配所选”。旧 VIDEO 库为保护历史语义保留混合范围，新动画/真人库分开匹配。扫描失败提示可独立忽略，不会停止扫描。

PDF.js 需要 Node ≥22.13，本地使用 Node 24 构建。依赖筛查确认的四项开发测试依赖问题已修复：Vitest 固定为 4.1.11，补齐 DOM 测试依赖，更新 source-map-js/Tinypool；依赖树完整，升级后全部测试通过，npm audit 为 0 项。Vitest 的修复范围见[上游公告](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9)。另增加 EPUB XML 深度限制及空白块的线性处理，避免异常小文件引发过量 CPU 开销。
